# Музыкальные данные King’s Valley: подтверждено по ROM

ROM SHA-256: 29d64ae6679838a7b3200b7ae8bf1e05807eda4a9f27bbd1d535205d024abd58.
Источник объяснений: MSXStudio/ROMS/KVALLEY/kvalley_Spain_2.asm, строки 10220–10879. Адреса и начало потоков сверены с ROM MSXLab, а не только с именами листинга.

## Адреса

- 7AA9 / 7AAF: выбор звука; ID в младших 6 битах. ID < 11 использует канал C, 11–16 — A/B, начиная с 17 — A/B/C. Старшие биты выбирают формат драйвера.
- 7B36: UPDATE_SOUND, перебор трёх состояний по 14 байт.
- E010, E01E, E02C: состояния каналов в RAM. +0 счётчик, +1 длительность, +2 ID/флаги, +3/+4 указатель потока, +5 октавный сдвиг, +6 базовая громкость, +7 текущая, +9 счётчик повтора, +10 tempo, +11 детюнинг, +12/+13 параметры программного затухания.
- 7BA3: NEXT_NOTE; FE — повтор, FF — конец.
- 7C5A: SET_NOTE, нотный формат при установленном бите 7 ID.
- 7CE9: таблица 12 периодов: 6A 64 5F 59 54 50 4B 47 43 3F 3C 38.
- 7CF5: таблица 34 указателей little-endian. Запуск задаёт индекс первой партии, последующие партии берутся из следующих ячеек.

## Нотный формат (бит 7 ID установлен)

- Dn: шаг длительности (tempo) в обновлениях драйвера, не BPM.
- Fn a b: базовая громкость n и два параметра программного затухания.
- E0–E7: сдвиг периода влево, то есть понижение высоты на октавы.
- E8–EF: ненулевой флаг детюнинга; драйвер добавляет единицу к периоду.
- 0n–Bn: индекс ноты в старшей половине байта; длительность = (n+1) × tempo.
- Cn: пауза с той же формулой длительности.
- FE count low high: повтор по абсолютному адресу; FF в count используется в имеющихся потоках для бесконечного цикла. Конечные повторы учитывают уже сыгранный проход; счётчик один на канал, не стек вложенных циклов.
- FF: завершение.

Период = table[pitch] << octave, затем при детюнинге +1. Частота = PSG clock / (16 × period). Ноты определены по реальным периодам; комментарий листинга «вторая октава» не использован как абсолютная нумерация MIDI.

| 29 | Гибель | 7DCE, 7DE0, 7DF2 |

Это индексы таблицы, не полные байты запуска: например, основная музыка запускается A=8B, начало игры A=97. Потоки гибели используют другой, частотный формат; подавать их в нотный декодер нельзя. Эффекты могут использовать прямой период, громкость, команды длительности 2n и шума 1n. Звук падения дополнительно изменяет данные в RAM.

## Практическая проверка

Из ROM извлечены основная партия и бас: research/music/ingame-rom-notes.json. 68 и 73 события (включая паузы), каждая партия имеет 768 тиков и возвращается к своему началу. В басовой партии раскрыты конечные повторы. Первые ноты основной партии: E4(24), F4(8), E4(24), F4(8), G#4(8), пауза(8), A4(8), пауза(8). Первые байты: D8 FC 03 03 E2 42 50 42 50 80 C0 90 C0.

Длительности пока выражены в вызовах драйвера. Для секунд требуется частота его вызова в выбранном режиме машины, а не безусловные 60 Гц. Извлечение статическое, сверка каждого события с живым драйвером ещё не выполнена. Декодер исследовательский: для двух проверенных потоков, не универсальный проигрыватель всех эффектов.

## Вывод для интерфейса

Добавить источник «ROM score» отдельно от «PSG capture». ROM сохраняет истинные границы повторных нот и команды циклов; запись PSG сохраняет фактическое звучание, включая затухание и эффекты. Не смешивать их происхождение. Пока интерфейс и MIDI продолжают использовать PSG capture; этот этап нашёл и описал исходные нотные данные.


## Просмотрщик реализован

Music · PSG → Ноты из ROM. Семь мелодий подтверждённой версии ROM; цветные партии A/B/C, отдельные кнопки видимости, таблица нот/пауз с адресами и исходными байтами, список управляющих команд. Щелчок по ноте выбирает её адрес в CPU-пространстве. Ноты из ROM показываются в тиках, без произвольного перевода в секунды. Проигрывание и MIDI в этом режиме пока не подключены; существующие кнопки остаются в PSG capture. Проверки tests/rom-music.mjs проходят для всех семи мелодий.
