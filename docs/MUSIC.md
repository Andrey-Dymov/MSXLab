# Спрайтовые слои и музыка

## Спрайты

Panels → Sprites → Colour composition показывает наложение аппаратных спрайтов MSX1. В таблице можно выключать отдельные слои, выбирать Solo и возвращать Show all layers. Так видно, из каких одноцветных частей складывается цветной объект. Учитываются прозрачность, координаты, early clock, 8/16 пикселей, увеличение и приоритет SAT. Ограничение четырёх спрайтов на строку отключено именно для исследования; это не точная копия экрана и не декодер MSX2 sprite mode 2. Для неподвижной композиции при исследовании нажмите Pause.

## Музыка

Panels → Music · PSG:

1. Record PSG начинает запись регистров трёх каналов AY-3-8910; если игра стоит, нажать Run.
2. Запустить нужную мелодию в игре, затем Stop capture.
3. Выбирать A/B/C: текущая нота, частота, громкость, графическая дорожка высоты/длительности и таблица событий. Оранжевым отмечаются шум/огибающая. График ограничен диапазоном C2–C6; высоты вне диапазона показаны на краю и подписаны в подсказке/таблице.
4. Выбрать предполагаемый темп. Раздел MSX BASIC содержит приближённый вариант PLAY для трёх каналов.
5. Save music сохраняет исходные регистры, кадры и транскрипцию в sessions проекта. Load music открывает сохранённую запись. Export BASIC записывает текстовый `.bas` в research/music проекта.

Запись берётся один раз на изменившийся кадр, максимум 7200 отсчётов. FPS определяется у VDP в начале записи. Пауза не добавляет отсчёты; восстановление состояния сбрасывает текущую запись. Это исследовательская транскрипция звучания, а не автоматическое извлечение оригинальной партитуры из ROM.

Ограничения: короткие внутрикадровые события могут теряться; эффекты, вибрато, огибающие и шум не переносятся точно в PLAY. Длительности округляются до шестнадцатых выбранного темпа, ноты повторно атакуются на каждом шаге. Вне диапазона O1–O8 экспортирует паузы. MML разбит на короткие синхронные фрагменты трёх каналов, чтобы BASIC-строки укладывались в 255 символов. Темп автоматически не определяется. Нотного стана и SCC/FM-поддержки пока нет.

## Источники

- [General Instrument AY-3-8910 datasheet](https://map.grauw.nl/resources/sound/generalinstrument_ay-3-8910.pdf): регистры генераторов тона, микшер, громкость, шум и огибающая.
- Локальные исходники WebMSX 6.0.8: PSG, PSGAudio и VDP. Используется внешний адаптер; файл поставки движка не изменялся. При периодах 0/1 WebMSX не генерирует обычный тон; такие значения не переводятся в ноты.
- [MSX Technical Data Book — BASIC reference](https://www.msxarchive.nl/pub/msx/docs/manuals/msxtech.pdf): синтаксис PLAY для трёх голосов, O/L/T/V. Ссылка найдена в поиске; сервер не разрешил повторно скачать PDF в этой проверке. Рабочая реализация использует стандартные команды O/L/T/V, A–G, # и R.

Проверки: контрольный PSG-тон 440 Гц → A4, микшер/тишина/огибающая, длительность событий, паузы, длины строк BASIC, запись на реальном ядре, сохранение/загрузка и изоляция проектов. Сгенерированная трёхканальная программа PLAY также выполнена до контрольной надписи в настоящем MSX BASIC внутри WebMSX. Это не проверка акустической идентичности восстановленной мелодии оригиналу.


## Прослушивание записи

Play воспроизводит три тональных голоса через Web Audio; Pause сохраняет позицию, Stop возвращает к началу. Вертикальная линия и ползунок показывают секунды; щелчок по дорожке перемещает позицию. При смене записи или проекта звук прекращается. Это звуковой синтез тонов по захваченным частотам и громкости, не точная эмуляция AY: шум пока не воспроизводится, аппаратная огибающая заменена постоянным уровнем. Звук игры независим; для отдельного прослушивания её следует поставить на паузу.


Export MIDI сохраняет .mid в research/music проекта: SMF 1, дорожка темпа и три дорожки PSG A/B/C, 480 PPQ, фиксированные 120 BPM с сохранением исходных времён. Экспортируются только каналы, включённые кнопками A/B/C; без выбранных каналов кнопка экспорта недоступна. Высота округлена до MIDI-ноты, громкость передана через velocity; шум и аппаратная огибающая не восстанавливаются.


## Общий проигрыватель для ROM и PSG

Оба источника используют один MusicPanel, useMusicPlayback, renderMusic и musicMidi. ROM-конвертер передаёт исходные события scoreNotes с адресами; повторные ноты сохраняются в MIDI даже при равной высоте без паузы. Для PSG изменения громкости внутри непрерывной ноты остаются CC expression. Общие кнопки A/B/C, Play/Pause/Stop, перемотка, Save/Load music, Export MIDI/BASIC. Для ROM пользователь выбирает 50/60 тиков в секунду; это предположение о частоте вызовов драйвера, а не измерение. Экспортируется один проход бесконечного цикла. Тембр, затухание и шум по-прежнему приближённые.


## Музыкальные блоки проекта

Labels → Музыка → + / Edit. Тип MUSIC с полем music: format, layout (streams/table), channels (адреса потоков либо число элементов таблицы), tickRate, periodTable, romBase. Для ROM адрес блока — смещение в файле; указатели каналов и таблица периодов — CPU-адреса с указанной базой отображения. Для CPU используются текущие байты памяти. Кнопка открытия блока выбирает его в Music.

Список мелодий теперь формируется из MUSIC-меток проекта, без проверки хеша и встроенных адресов в UI. Описание музыкальных блоков хранится в проекте. Декодер читает настраиваемые таблицы и потоки; другие форматы требуют нового декодера в реестре. Неизвестный формат выдаёт ошибку. Настройки сохраняются, экспортируются и импортируются вместе с метками. Расшифрованная партитура фиксируется при выборе блока; для изменённых данных CPU следует повторно выбрать источник или блок.
