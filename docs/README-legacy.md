# MSXLab 0.8

Рабочая ранняя версия desktop-лаборатории MSX: Electron, React, TypeScript, Dockview и отдельный адаптер WebMSX 6.0.8. Основной проект — King’s Valley. Интерфейс больше не является набором заглушек.

## Запуск

На этом Mac готовую сборку можно открыть двойным щелчком по `Start MSXLab.command`. Повторный запуск поднимает существующее окно. После изменения исходников сначала выполните сборку.

```sh
npm install
npm run build
npm start
```

Разработка с обновлением интерфейса: `npm run dev`. Веб-режим без Electron показывает оболочку; файловые проекты требуют desktop-моста. Все зависимости и материалы уже находятся в этом локальном проекте.

## Основной маршрут

1. Выберите King’s Valley в Projects и дождитесь экрана игры. Кликните Screen, затем нажмите пробел.
2. Pause останавливает CPU на границе инструкции. Step Into выполняет следующий шаг, Step Over проходит вызов. Run продолжает, Reset перезапускает окружение.
3. Выберите адрес в коде, метках или карте: связанные просмотры памяти переходят к нему. Адрес/имя метки можно ввести в верхней строке.
4. Точка в левой колонке дизассемблера включает breakpoint. В Breakpoints доступны отключение и простые условия, например `A == $12`.
5. Все остальные инструменты находятся в Panels. Знак `+` создаёт дополнительный экземпляр поддерживаемого просмотрщика. Настройки — шестерёнка рядом с темой.

Кнопки запуска воздействуют на настоящую машину. Выбор адреса не меняет PC. Закрытие/перемещение Screen не пересоздаёт движок.

## Реализовано

- Тёмная и светлая темы; docking, вкладки, закрытие/повторное открытие, Reset layout; сохранение раскладки, темы, проекта и параметров основных просмотрщиков.
- Запуск ROM, импорт нового проекта из ROM/COM/BAS. Для DOS-программ строится 720KB FAT12-диск с локальными MSXDOS.SYS и COMMAND.COM; для BASIC — диск и автоматический RUN.
- Пауза, продолжение, шаг, проход вызова, выполнение до адреса, несколько адресных остановок и условия сравнения регистров.
- Редактирование RAM/VRAM и регистров на паузе; отмена последней записи памяти с проверкой конфликта. ROM и области управления картриджами не редактируются.
- CPU/VRAM/исходный ROM, HEX, текст ASCII, знаковые/беззнаковые числа 8/16/32 бит, float32, LE/BE для 16 бит, следование выбору/PC/HL/DE и закреплённые адреса.
- Дизассемблер со знаковыми смещениями, переходом к цели команды и историей адресов; регистры и флаги, стек, наблюдаемые байты, живая карта первичных/вторичных слотов с PC/SP и выбором.
- Импортированы 2020 корректных меток, 75 шаблонов и исходный листинг King’s Valley. Оригиналы JSON сохранены. Метки, комментарии, типы и диапазоны редактируются и автоматически записываются на диск.
- Поиск чисел, текста и байтов с маской ?? в диапазоне; сравнение двух снимков, точная разница и сужение кандидатов, watchpoints диапазонов CPU/VRAM и портов I/O, включая запись неизменного значения, журнал последних записей с PC.
- Просмотр упакованных битмапов, шрифтов/тайлов, MSX1 tilemap, атрибутов и паттернов спрайтов, палитры, простых структур, графиков и настраиваемой несжатой карты тайлов уровня.
- Снимок экрана, исследование аппаратных спрайтов на остановленном кадре и сохранение выделенного фрагмента.
- Ограниченная трасса, счётчики посещений инструкций, прямые ссылки/граф по размеченным процедурам.
- Undo/Redo последних 50 исследовательских изменений, именованные версии исследования, сохранение/восстановление машины, экспериментальная запись/повтор клавиатуры.
- Документация общей библиотеки и текстовые файлы research/resources выбранного проекта доступны в Documentation.
- Отдельный явно обозначенный Mock backend с согласованным тестовым сценарием.

## Разметка кода и сохранённые раскладки

В Disassembler доступны **Code + data**, **Procedure** и **Raw Z80**. Первый учитывает типы меток, второй показывает процедуру от начала до конца, третий декодирует байты без учёта разметки. Заголовок блока показывает имя, диапазон, длину и описание; Edit block редактирует их. Переходы PROC ведут к соседним процедурам. Если команда пересекает заданную границу блока, байты сохраняются как DB с предупреждением: границу нужно проверить, она не исправляется автоматически.

Метки DATA/DB выводятся как байты, DW — слова little-endian, DEC1/DEC2 — десятичные значения; MSG/SCR показывают ASCII-предпросмотр. Коды MSX и графические форматы не подменяются предполагаемым текстом. Для BM1/BM2/BM4 кнопка Open block view открывает битмап с соответствующей глубиной цвета. Для других типов открываются числа, текст, HEX или отдельная процедура. Создаётся независимая вкладка, которую можно переместить; настройки входят в сохранённую раскладку.

В Labels есть фильтр PROC/DATA/COMMENT/AREA, отбор по текущему адресу, диапазон и длина. Длина задаётся в десятичных байтах, адреса — в HEX, конечный адрес включается. Import / export читает JSON MSXLab/MSXStudio и простые символы `NAME: EQU $4015`, `NAME = 0x4015`, `4015 NAME`. Адреса символов считаются шестнадцатеричными. Предварительный просмотр показывает ошибки и совпадения. По умолчанию существующие записи сохраняются; обновление совпадающих имени, типа, адреса и пространства включается явно. Исходники импортов остаются в `research/imports`, экспорты — в `research/exports`. Импорт можно отменить через Research History.

References сканирует размеченный код, пропускает DATA и не дублирует перекрывающиеся процедуры. Доступны ссылки в выбранную процедуру и из неё, отдельный отбор вызовов. Это статический анализ текущего снимка, а не полный динамический граф; косвенные переходы не разрешаются.

Карта памяти переключается между CPU и VRAM. Основная полоса отображает подключённые слоты CPU или размер VRAM; тонкая полоса — области проекта, процедуры и данные. Наведение показывает описание. Разметка использует логические адреса, без отдельных условий для банков картриджа.

Кнопка **Layouts…** сохраняет текущее расположение под именем. Apply восстанавливает, Update заменяет выбранный вариант текущим, Rename переименовывает, Delete удаляет. Сохраняются группы, размеры, вкладки, дополнительные экземпляры и настройки панелей. Раскладки общие для проектов и переживают перезапуск; применение не меняет проект, тему и запущенную машину.

## Проекты и обновление сборок

`projects/<id>/project.json` содержит версию формата, окружение, метки, breakpoints и watches. Подпапки: `program`, `environment`, `research`, `resources`, `captures`, при необходимости `sessions` и `builds`.

Новые сборки публикуются неизменяемыми комплектами в `builds/<content-hash>/`: программа, диск и описание. Только после готовности всего комплекта атомарно переключается `project.json`. Старый комплект остаётся доступным даже при сбое обновления. Записи одного проекта выполняются последовательно.

Основной проект содержит копии файлов MSXStudio. Старое приложение не изменяется. При замене сборки прежняя программа и её манифест архивируются в `builds`; разметка получает предупреждение о несовпадении версии до явной проверки пользователем.

Общее DOS-окружение находится в `resources/environments/msxdos1`, справочники — в `docs/reference`. Выбор файлов окружения доступен через Launch setup; полноценный каталог общих ресурсов с поиском и описаниями ещё не реализован.

## Практическое исследование памяти и спрайтов

В Labels у DATA-меток кнопка **☆** добавляет значение CPU в Watches, **W** ставит остановку на запись блока. Те же действия доступны в результатах Search / Memory Changes. Повторное добавление того же диапазона не создаёт дубликат.

**Search** ищет число выбранного формата, UTF-8 текст или байты (`3E ?? 32`). Диапазон задаётся в HEX; числа — обычным числовым значением. Для многобайтовых чисел можно включить выравнивание. Поиск использует свежий снимок; показываются его номер и пространство. Сохраняются первые 10 000 совпадений, общий счётчик включает все; страницы показывают по 100.

**Memory Changes**: Baseline → поиграть → Compare now. Кроме changed/same/increased/decreased доступны **equal** (новое значение равно заданному) и **delta** (разница равна заданной, например -1). Keep matches & next baseline оставляет кандидатов и переносит точку сравнения. Изменение диапазона/формата/источника или новый запуск очищают временные результаты. Сравнение ограничено диапазоном 1 MB и 100 000 кандидатами; при превышении предлагается сузить условия.

**Write Watchpoints** показывает конкретный доступ: адрес памяти, значение до/после, переданный байт, PC автора и имя содержащей процедуры. Go to writer ведёт к команде, Go to accessed memory — к данным. Это две разные позиции: текущий PC уже находится после команды. Для I/O сохраняется также полный порт. Вход в прерывание отмечается отдельно. Если наблюдение включено посреди уже выполняемой инструкции, её автор помечается как неизвестный до первой отслеженной границы; API помечает такой PC как `pcKnown: false`.

В **Sprites** и **Screen → Inspect** доступны Watch attributes и Watch pattern: остановка на записи четырёх байтов атрибутов либо 8/32 байтов паттерна. При срабатывании можно перейти к команде OUT и размеченной процедуре переноса в VRAM. Это не автоматическое восстановление игровой логики или сжатого исходного ресурса.

**Documentation → Project files** открывает текстовые документы из research/resources текущего проекта. Для King’s Valley сохранены `lives-investigation.md` и `sprite-writer-investigation.md`: проверенные адреса, наблюдения и порядок повторения. Исследование жизней подтвердило E050, переход 4 → 3 и DEC (HL) на 416C внутри INIT_STAGE.

## Настройки и профили запуска

В Projects нажмите **Launch setup…**. Можно выбрать проверенную модель MSX1E/MSX1J и зарегистрированный движок, подключить ROM во второй слот. Для DOS/BASIC добавляются файлы в корень загрузочного диска под именами DOS 8.3. Для DOS доступны совместимая пара MSXDOS.SYS / COMMAND.COM и однострочная команда AUTOEXEC. Основная программа остаётся APP.COM или APP.BAS. **Save & restart** собирает целый комплект и перезапускает проект.

Выбранные файлы копируются в проект, их SHA-256 фиксируется. Обновление программы сохраняет эти версии ресурсов; изменение исходных файлов снаружи не подменяет окружение. Изменение закреплённой копии обнаруживается при пересборке. Оригинальные файлы не перемещаются и не удаляются. Неудачная сборка не переключает проект на частично записанный комплект.

В том же окне **Save profile** сохраняет текущее окружение под именем. **Apply & restart** возвращает выбранные машину, движок и дополнительные ресурсы, используя последнюю сборку основной программы. **Delete** удаляет только описание профиля. Сначала примените изменения формы, затем сохраните профиль. Профили запуска принадлежат проекту; **Layouts…** отдельно управляет расположением панелей.

В **Session & Replay** можно сохранить несколько состояний под именами и выбрать нужное для восстановления. Состояния и записи клавиатуры проверяются по проекту, программе, движку и отпечатку комплекта запуска. После изменения окружения несовместимая запись отклоняется. Восстановление очищает журналы записей, I/O, трассу и счётчики профилирования; сами режимы наблюдения остаются включёнными. Во время активной записи клавиатуры сначала нужно нажать Stop recording. Старые состояния без отпечатка допускаются только для старого проекта без такого отпечатка; для нового комплекта нужно сделать новое состояние.

Пока проверены MSX1 и MSX-DOS 1. Выбор произвольного файла не гарантирует совместимость DOS 2/Nextor, нестандартного BIOS или дополнительного картриджа. Диск — один FAT12 720 KB, файлы размещаются в корне. Неиспользуемые копии ресурсов и старые комплекты автоматически не удаляются.

## Движок

Оригинальный `engines/webmsx-6.0.8/wmsx.js` скопирован из официального релиза без правок. Источник и SHA-256 зафиксированы в `engines/config.json`. Проект выбирает зарегистрированный engine ID. Для новых комплектов и профилей сохраняется отпечаток файла движка; несовпадение отображается как ошибка, чтобы другая версия не запускалась незаметно. Для другого движка нужен другой адаптер; неизвестная версия не считается автоматически проверенной.

Адаптер в `public/engine/boot.js` работает внутри изолированного iframe, без Node.js. Панели общаются с ним через `DebuggerBackend` и сообщения. Реализация использует внутренние методы WebMSX и перехват тактов в памяти процесса. На диске vendor-файл не меняется.

## Важные границы текущей версии

- Отладочные операции проверены на MSX1 / Z80 1×. R800, турбо, MSX2 и все варианты банков не заявляются проверенными.
- CPU останавливается точно на границе инструкции, но VDP заканчивает текущий проход. Это не общая остановка на одном такте; пошаговая работа может менять поведение программ, зависящих от времени.
- Вход в ожидающее прерывание может быть отдельным шагом. Шаг через вызов использует адрес возврата и SP, с тайм-аутом около пяти секунд; сложные вложенные случаи требуют дальнейшей проверки.
- Watchpoints срабатывают после доступа/инструкции. Чтения CPU включают выборку инструкций. I/O сопоставляется по младшему байту порта; журнал сохраняет полный адрес. Журнал памяти показывает изменяющие попытки записи, а не гарантирует запись в физическую RAM для любого маппера.
- Трасса ограничена 500 записями и хранит регистры, но не исторические снимки всей памяти. Исторические регистры явно отделены от живой памяти.
- Профилировщик считает посещения адресов, не точное время процедур. Статический граф не разрешает косвенные переходы.
- Аппаратные графические декодеры рассчитаны на MSX1; пользовательские сжатые форматы игр, составные метатайлы и MSX2 ещё не поддержаны полностью.
- Запись воспроизводит клавиатуру по кадрам из исходного снимка. Джойстики, контрольные события и строгая детерминированность между сборками пока не реализованы.
- Просмотр исходников связывает блоки только по совпадающим именам меток. Универсальной отладки исходников C/BASIC пока нет.

Полное ТЗ шире этой реализации. Матрица состояния — в `docs/IMPLEMENTATION.md`.

## Внешний интерфейс и MCP

При запуске создаётся `.msxlab-runtime.json` с адресом локального API и временным секретом. Файл приватный и исключён из git. API слушает только loopback. POST-запросы требуют `Authorization: Bearer <token>`; тело: `{ "command": "status", "args": {} }`.

Команды: `status`, `projects`, `loadProject`, `run`, `pause`, `step`, `until`, `registers`, `readMemory`, `capture`, `reset`, `createProject`, `updateBuild`, `writeMemory`, `setRegister`, `setBreakpoints`, `setWatchpoints`, `stepOver`, `trace`, `readTrace`, `configureLaunch`, `launchProfile`, `listCheckpoints`, `saveCheckpoint`, `restoreCheckpoint`, `searchMemory`.

Пауза, шаг и выполнение до адреса отвечают после остановки, возвращая `status`, `registers`, `hit`. Недостижимая цель останавливается по тайм-ауту; причина — `run-to timeout`. Команды управления API выполняются последовательно.

Пример сценария внешней сборки: `createProject` принимает `sourcePath` для ROM/COM/BAS; `updateBuild` принимает `id`, `sourcePath` и `run: true`, пересобирает диск и перезапускает проект. Ассемблер или C-компилятор запускается снаружи.

`configureLaunch` принимает `id`, `options` и необязательный `run: true`. В options: `machine`, `engine`, `name`, `addFiles: [{name, sourcePath}]`, `removeFiles: [name]`, `dos: {systemPath, commandPath}` (null возвращает общую пару), `secondaryRom: absolutePath` (null отключает), `bootCommand`. `launchProfile` принимает `id`, `action: save/apply/delete`, `name` для сохранения или `profileId` для применения/удаления; `run: true` запускает применённый профиль. Эти команды доступны и в MCP.

`listCheckpoints` возвращает сохранённые состояния активного проекта. `saveCheckpoint` принимает `name` и явный `replace: true` для перезаписи. `restoreCheckpoint` принимает `name` и проверяет совместимость перед восстановлением; `@legacy` обозначает старое одиночное состояние. После сохранения через API кнопка **Refresh checkpoints** обновляет список в панели.

`searchMemory` ищет по свежему снимку: `query`, `mode: number/hex/text`, `space`, `format`, `start/end`, `aligned`, `offset/limit`. Ответ содержит общий счётчик, число сохранённых совпадений, номер снимка и метки совпавших адресов. `status.hit.access` содержит детали последней остановки по памяти: адрес, значение, автор и его определённость.

Локальный stdio MCP:

```json
{
  "mcpServers": {
    "msxlab": {
      "command": "node",
      "args": ["/path/to/MSXLab/scripts/mcp.mjs"]
    }
  }
}
```

Сначала запустите MSXLab. Мост поддерживает handshake-протоколы MCP 2024/2025; новый stateless lifecycle 2026 не реализован. Подключение к клиенту автоматически не устанавливалось. Протокол инструментов сверялся с [официальной спецификацией](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/main/docs/specification/2025-06-18/server/tools.mdx).

Интеграционные проверки запускают отдельное окно Electron с отдельным профилем. Изменяемые проекты создаются временно и удаляются после проверки. Тесты не нужно запускать одновременно: файл обнаружения локального API общий.

## Структура исходников

- `electron/` — окно, локальная доставка ресурсов, ограниченный preload/IPC, атомарные записи и FAT12.
- `src/backend/` — контракты, адаптер сообщений, demo backend, Z80-декодирование и VDP-интерпретация.
- `src/state/` — общее состояние исследования и параметры экземпляров панелей.
- `src/components/` — независимые инструменты.
- `public/engine/` — интеграция неизменного WebMSX в браузерном контексте.
- `engines/` — конфигурация и оригинальные поставки движка.
- `projects/`, `resources/`, `docs/reference/` — проекты, окружения и документация.

### Чтение исследования через API/MCP

- `readLabels`: query, type, space, address (содержащие адрес блоки), offset, limit (1–500). Ответ содержит полные описания и длины.
- `readDisassembly`: address, mode (`annotated`, `raw`, `procedure`), limit (1–500). Возвращает снимок листинга, метаданные процедуры и текущие слоты CPU.
- `readReferences`: address, direction (`all`, `incoming`, `outgoing`), offset, limit. Возвращает прямые ссылки из размеченного кода.

Команды только читают состояние и не меняют PC или разметку.

### Активность памяти

На полосах CPU и VRAM добавлены переключаемые гистограммы с логарифмической высотой и нормировкой каждого слоя. CPU: выполнение, чтения, записи; VRAM: чтения и записи CPU. Сбор включается кнопкой Activity, сброс — ↺. Проверены счётчики на контрольной программе, исключение чтений отладчика, пауза сбора, сброс и восстановление состояния. Подробности: [Активность памяти](ACTIVITY.md).
