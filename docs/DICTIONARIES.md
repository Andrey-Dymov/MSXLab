# Общие справочники: аудит MSXStudio и требования MSXLab

## Проверено в старой системе

Исходный проект: /path/to/MSXStudio.
modules/msx.js:128–145 задаёт порядок: loadMSXVars, z80InstructionSetJSONLoad (с резервным набором), ROM, отладчик, loadExtAsm, loadLabels, loadPatterns, loadData, дизассемблирование.

- data/msxvars.json: 737 записей BIOS, переменных и хуков; имя, адрес, длина, описание. Загрузчик modules/loader.js:297.
- data/instructions.json: таблицы Z80 main/ED/CB/DD/FD/DDCB/FDCB; байты, мнемоники, размер, такты, описание, признак адреса. Это самостоятельный справочник декодирования, не метки памяти.
- ROMS/<проект>/extasm.json: внешнее описание листинга. Загружается перед labels.json; комментарии переносятся к адресам, создаются служебные COMMENT с именами __<имя>_<номер>.
- ROMS/<проект>/labels.json: исследование проекта, включая процедуры, данные и области.
- data/macros.json: 75 шаблонов; объединение по нормализованному имени через unionBy.
- data/msx_ports.json: 32 описания портов с направлением и вариантами MSX. В modules не найдено использования этого файла; наличие файла не означает работающую загрузку.
- modules/core/msx/variables.js содержит прежние загрузчики XHTML, varshooks.txt и z80full.json. Их вызовы при запуске закомментированы.

modules/msx.js:setLink ищет системный адрес или адрес минус один, подставляет имя со смещением и описание. Затем точная метка проекта (кроме AREA) заменяет системное имя. Исходный адрес сохраняется как commentLink. Длина объекта при таком поиске не проверяется.

Недостатки данных: шесть адресов с несколькими записями; одна некорректная/неположительная длина. У H.KEYI FD9A указана длина 1 вместо 5 (сверено с локальным Red Book). Дубликаты надо различать как допустимые псевдонимы или конфликты, а не удалять вслепую. Синхронный loadFile блокирует загрузку; централизованной версии пакетов и диагностики конфликтов нет.

## Требуемый механизм MSXLab

Это проект решения, ещё не подключённый к runtime. Сейчас researchIndex использует метки проекта, декодер — отдельную таблицу opcodes.json; общего разрешения системных имён нет.

1. Версионированные пакеты общей библиотеки: BIOS, рабочая область и hooks, I/O-порты, DOS/Nextor, Z80, шаблоны. Проект хранит выбранные пакеты/версии и свои переопределения, а не копию общей базы.
2. Manifest каждого пакета: id, версия схемы, источник, совместимые машины/окружение, список файлов. Загрузка асинхронная, проверка структуры и диапазонов; список успешно загруженных пакетов, ошибок и конфликтов виден пользователю.
3. Запись символа: стабильный id, имя и псевдонимы, тип, адресное пространство, адрес и достоверная длина, описание, источник, область применимости (машина, BIOS, слот/банк при необходимости). Не смешивать CPU, VRAM, ROM-offset и I/O с одинаковыми числами.
4. Единый resolver для дизассемблера, памяти, подсказок, поиска и переходов. Приоритет: явная метка проекта, затем применимые системные пакеты. Внутри уровня сначала точное совпадение, затем содержащий диапазон; конфликты явные и детерминированные. COMMENT не символ; AREA не заменяет операнд.
5. Смещение NAME+n только внутри подтверждённого диапазона. H.KEYI охватывает FD9A–FD9E: FD9B выводится как H.KEYI+1. Нельзя угадывать длину по следующему имени.
6. Подстановка по разобранному операнду: адрес перехода, абсолютный операнд памяти, порт. Не заменять случайные числовые константы. Косвенные адреса показывать как вычисляемую подсказку из регистров, не переписывая (HL) именем.
7. BIOS-имена применять с учётом отображённого BIOS/слотов; DOS-пакеты подключать по профилю проекта. Не называть RAM по адресу ROM, если BIOS отключён.
8. Names/Addresses сохраняется; имя светлее мнемоники; подсказка содержит числовой адрес, диапазон, назначение и источник. Системные записи доступны для просмотра отдельно от редактируемых меток проекта.
9. Импорт старых данных с отчётом и проверенными поправками, сохранением оригинала и происхождения. Не переносить автоматически генерацию видимых служебных имён комментариев.

## Приёмка

FD9A → H.KEYI; FD9B → H.KEYI+1; FD9F → следующий собственный hook, без выхода за диапазон. Проектное имя перекрывает системное без изменения пакета. Порт 98h не становится символом CPU 0098h. Проверяются неподходящий профиль, смена слотов, конфликты, битый пакет, отсутствие справочника, независимость проектов, подсказки и переключение Names/Addresses.

## Реализовано: общая библиотека v1

Два типа TypeScript: SymbolEntry и PatternEntry. src/data/library.json содержит пакет msx-common версии 1: 737 записей системных имён, 32 порта и 75 шаблонов из старого проекта. Исходные файлы не изменялись. Исправлены длины пятибайтовых хуков; некорректная длина ограничена одним байтом. Старые адреса найденных совпадений шаблонов не переносились: они относятся к конкретной игре.

Пакет включён в сборку и загружается автоматически. Labels / Shared symbols — поиск и просмотр источника; Patterns / Shared library — добавление шаблона в проект для сканирования. Системная библиотека не записывается в labels проекта. Дизассемблер подставляет имена для прямых переходов, абсолютных обращений к памяти и портов. Числовые константы и регистровые операнды не заменяются. Подсказка сохраняет числовую инструкцию, описание и источник. Метки проекта имеют приоритет; COMMENT/AREA исключены. Проверка BIOS использует текущую карту страниц.

Ограничения первой версии: выбор отдельных версий/пакетов в профиле пока не реализован; данные старого справочника ещё требуют полной проверки по моделям MSX и версиям BIOS. Разрешение дубликатов детерминировано, но отдельного редактора конфликтов пока нет. Шаблоны копируются в проект только при явном добавлении. Таблица инструкций дизассемблера не изменялась и не стала третьим типом справочника.

Проверки tests/library.mjs: H.KEYI+1, граница H.TIMI, приоритет проекта, отображение BIOS, раздельные CPU/I/O, сохранение числовых констант.
